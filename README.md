# article-skill｜SCI 文献精读与图文 Word 总结

**给 Agent 一篇完整 SCI 论文 PDF，得到一份围绕研究主线展开、配有原文图片的中文精读总结。**

article-skill 是捶捶自己开发的 SCI 文献精读与总结技能，适用于论文精读、组会准备、研究交流和科普写作素材整理。它将阅读、写作、图片处理与 Word 排版要求整理成可复用流程，减少每次重新描述需求的工作。

> 使用 article-skill 技能，帮我总结这篇文献并生成一个 Word 文件。

## 你会得到什么

一份以中文总结标题命名的可编辑 Word 文档，包含原论文题名、作者和单位地址截图，以及五个部分：

| 部分 | 内容 |
|---|---|
| 研究背景 | 三段式：研究问题与背景、已有研究及不足、研究目的与思路 |
| 研究方法 | 按实际研究归纳材料或试样制备、实验、表征、模拟和数据分析，保留必要操作细节 |
| 主要结论 | 至少五项有依据的发现，按研究逻辑组织，围绕结论阐述证据与解释 |
| 创新点 | 归纳有原文依据的贡献，讲清具体增量及意义，不编造创新 |
| 引用格式 | 引用当前论文自身，已核实的 DOI 单独置于末尾 |

需要时，可以同时要求导出 PDF。每篇论文单独整理，后续修改保留旧稿。

## 与直接让 AI 概括论文有什么不同

- **围绕结论展开。** 先梳理整篇研究主线，再组织内容，避免把主要结论写成逐图介绍和数据清单。
- **图片辅助理解。** 使用原论文图片，按总结顺序编号；图注解释真实子图，裁剪时保留坐标、单位、图例和比例尺。
- **突出选题特色。** 标题兼顾清晰与吸引力，核心方法如分子动力学、DFT确实重要时，可以保留其辨识度。
- **先审内容，再排版。** 对照原文核查关键陈述、数值、图文对应和贡献依据，再检查 Word 的实际页面。
- **便于继续修改。** 每篇保留原文、草稿、图片和问题记录，方便在同一任务中继续完善。

这些流程帮助约束生成质量，但不能代替原文核验。模型能力、论文难度和运行环境仍会影响结果。

## 安装

### 通过 Skills CLI 安装

如果已配置 Node.js（当前 Skills CLI 要求 22.20 或以上），可在终端运行：

```sh
npx skills add ws-cczj/article-skill --skill article-skill
```

按提示选择使用的 Agent。此命令默认安装到当前项目；需要跨项目使用时可追加 `-g`。这是可选安装方式，不要求所有用户安装 Node.js。安装成功不代表 Python、字体及文档渲染环境已经准备完成。参见 [Skills CLI 官方说明](https://github.com/vercel-labs/skills)。


### 让 Codex 帮你安装

在支持技能安装的 Codex 中发送：

> 请使用 skill-installer，从 GitHub 仓库 ws-cczj/article-skill 安装仓库根目录的 skill，路径为 .，安装名为 article-skill。

仓库根目录就是技能目录，不需要再选一个子目录。安装后在新对话中确认 `article-skill` 可用。

### 手动安装

下载[仓库 ZIP](https://github.com/ws-cczj/article-skill/archive/refs/heads/master.zip)，解压后将文件夹命名为 `article-skill`，放入：

```text
~/.codex/skills/article-skill/
```

若设置了 `CODEX_HOME`，则放入 `$CODEX_HOME/skills/article-skill/`。确保文件夹内直接包含 `SKILL.md`、`references/`、`scripts/`、`agents/`、`requirements.txt` 和 `LICENSE`，避免多套一层文件夹。

其他支持技能的 Agent 可按其安装方式加载本仓库；尚未逐一验证所有客户端的兼容性。

## 开始使用

附上完整论文 PDF，再发送：

> 使用 $article-skill，总结这篇论文，生成 Word 文档。

想同时保留 PDF：

> 使用 $article-skill，总结这篇论文，生成 Word，并导出同名 PDF。

处理多篇论文：

> 使用 $article-skill，分别总结这些论文，每篇单独生成 Word 文档。

你不需要填写 JSON、编写 Python 脚本，或重复提供写作模板。可以补充关注点，例如“标题体现分子动力学特色”或“重点讲清性能变化的机制”；具体内容仍以原文为准。

## 使用前需要准备什么

- 能读写文件、运行 Python、阅读 PDF 与图片的 Agent。
- 可访问的 Python 3.10 或以上运行环境。技能会引导 Agent 查找可用环境，并在独立虚拟环境中准备依赖，通常无需手动配置。
- 用于 Word 页面复核的 Microsoft Word、LibreOffice，或其他可用的文档渲染工具。
- 宋体、楷体、Times New Roman。缺少字体时，排版可能与预期不同。

Skill 本身不包含模型、Office 或字体。纯文字聊天环境不能直接执行完整的文件生成流程。遇到环境问题时，可让 Agent 按[环境说明](references/environment-setup.md)检查。

## 文件保存在哪里

Agent 会告诉你本次论文目录的绝对路径。最终文件位于 `final/`，其余目录用于保存阅读与修订材料：

```text
本篇论文目录/
├── source/    原论文与提取文本
├── assets/    原文裁图
├── draft/     总结草稿
├── review/    核查与页面预览
├── memory/    研究主线和问题记录
└── final/     最终 Word，以及按需导出的 PDF
```

每篇独立整理，不混用其他论文的数据和图片。如果 Agent 运行在云端，目录位于该任务的运行环境中，可让它提供成稿下载链接。

## 常见问题

**需要再提供格式模板吗？**
不需要。章节、图注、引用及 Word 字体字号已内置；有特别要求可以另行说明。详细格式见[成稿规范](references/output-formats.md)。

**能自动保证内容完全正确吗？**
不能。技能提供核查流程，不能保证模型不出错。重要数值、机制解释和引用应在使用前核对；扫描件或复杂版面可能需要额外识别。

**会检查更新吗？**
每次新总结任务开始时，通过 HTTPS 对比 GitHub 与本地技能文件，一致时不重复下载，不要求安装 Git。网络或接口限流导致无法检查时会说明原因；你也可以明确要求离线使用当前版本。

**旧版需要重新安装吗？**
此前使用 `academic-paper-summary/` 或 `academic-summary/` 子目录的用户，需要手动安装一次当前根目录版本。确认新技能可用后，将旧技能移出扫描目录，避免重复加载。已有论文和用户级 Python 环境可以保留。
