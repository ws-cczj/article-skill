# 总结前检查并更新skill

每次开始一项新的文献总结任务，先检查官方GitHub仓库 `https://github.com/ws-cczj/article-skill.git` 的默认分支，再读取本次要执行的规则。更新范围为仓库根目录中的完整技能文件。同一任务的续写、修订和多篇批量处理只在开始时检查一次，固定本轮版本，避免生成中途换规则；仅审阅已有文档或开发skill不执行自动更新。

## 确定最新版本

先用可访问的Python执行实际安装目录中的标准库脚本（不需先安装论文处理依赖）：

```text
"<Python绝对路径>" "<实际skill目录>/scripts/check_skill_update.py" --skill-dir "<实际skill目录>"
```

脚本只通过HTTPS查询GitHub API的默认分支、提交SHA和文件哈希清单，再与本地完整skill内容比较。无需Git CLI、.git目录或第三方Python依赖；GitHub API路径中的git/trees只是服务端接口，不是执行Git命令。检查阶段不下载仓库快照、不clone。

- `content_equal`：完整文件清单与内容一致，立即继续，不下载。
- `different_unversioned`：内容确实不同，但可能是旧版或本地定制；不能仅凭差异宣称远程更新。不覆盖本地定制，按下节备份或隔离使用已核实的官方提交快照。
- `unknown`或失败：没有确认版本。按失败流程报告网络或API限流，不以clone绕过。

只有内容不同且需要采用官方版本时，才通过HTTPS下载该SHA的完整快照，校验来源与提交身份。旧安装没有可靠版本记录时，以文件清单比较为准，不用时间戳猜新旧。同一任务只检查一次。维护者提交和推送项目可使用自己的Git CLI，与用户运行skill的前置检查无关。

## 更新和使用

- 完整目录安装（包括复制、ZIP或来自仓库的目录）：将暂存中的完整新版skill部署到实际技能目录，先把旧目录完整备份到技能目录之外，再替换；检查所有绝对路径，不能递归操作上级目录。失败恢复旧目录，并明确本轮更新未完成。不要仅覆盖已有文件而遗留新版已删除的规则。原目录若混有论文、输出或环境，先完整保留，禁止当作过期规则删除。
- 已知本地定制、工作区未提交修改、分叉或无法判断是否可以安全替换时，不覆盖原目录。可将已核实的官方版本放在独立目录，明确告知本轮使用该目录，并从其中读取规则、执行脚本；保留原安装与所有本地工作。这是本轮使用最新版，不得称原安装已更新。

无需再次征求常规更新许可。不可写或不能安全完成时给出具体障碍，不绕过权限。用户显式固定版本或要求离线使用时尊重该要求，并说明未采用最新版本。

更新后重新读取新版SKILL.md及当前阶段需要的参考文件，从同一版本执行脚本，不混用先前加载的旧规则。本轮完成检查即满足新版入口的更新步骤，不递归重启更新检查。此后按新版环境流程复用专属.venv并检查依赖变化；环境和首次欢迎状态保留在用户skill-state，不能因更新清除。宿主无法在本轮加载新版时明确要求重新开始任务，不假装新版本已生效。

## 失败与记录

无法访问GitHub、无法确定SHA、快照不完整或更新失败时，不能声称已经是最新版，也不默认跳过这项要求开始总结。先完成可行的诊断；仍失败则报告原因，等待用户明确选择离线使用现有版本或恢复网络后继续。不要无限重试。

论文目录创建后，在现有memory/synthesis.md简记检查时间、官方提交SHA、实际执行目录和结果（内容相同/更新安装/隔离使用新版/用户指定版本）。不记录凭据，不新增审核表。更新完成不等于论文内容审查通过。

仓库根目录同时可能承载本地开发文件。比较与更新排除.git、.venv、outputs、artifacts、tmp、__pycache__、.agents、.skill-check及本地发行ZIP；这些本地数据不随更新删除。技能更新不得将用户论文输出当作远程已删除的代码。
